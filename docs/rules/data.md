# 数据生命周期（data）

> Schema 演进与迁移的唯一规则是 migrations.md；所有权与一致性模式见。本文件定义备份、保留、软删、删除与导出约定（对应补齐清单「数据生命周期」P0 项）。

## 1. 所有权与边界（红线重申）

- 模块独占表；禁跨模块 JOIN/事务/外键；跨模块只存 ID，取数走 Port。
- DB 是唯一真相源；缓存不是（AGENTS §2）。

## 2. 备份与恢复

- PostgreSQL：**每日全量 + WAL 归档（PITR）**；备份文件加密存放，不含明文密钥。
- 备份与恢复方案随部署形态落地（后为裸机/物理机方案）；**恢复演练每季度一次**（初始基线，可调严不可调松）并记录（行数/校验和抽样比对，同口径）。
- 迁移前备份是破坏性操作的前置条件（全局红线）。

## 3. 保留与清理

| 数据 | 默认保留 | 清理方式 |
|------|---------|---------|
| operation_logs（审计） | 180 天 | audit 模块 Job（保留期可配，downstream guide 同值） |
| scheduler_runs / Job 日志 | 由模块配置声明 | scheduler 清理 Job；**未声明保留期不得自动删除** |
| upload_record / 临时上传 | 由 storage 配置声明 | 模块自带清理 Job |
| Outbox 已投递 / Inbox 已消费 | 由模块配置声明 | 定期清理 Job |

- 原则：**一切自动删除必须有显式声明的保留期**；无声明的数据只增不删。

## 4. 软删规范（前置规则：migrations.md「软删」行）

- **按表声明**（Manifest `soft_delete`）；默认硬删 + 审计，禁止全表默认软删。
- 启用软删的表：统一列 `deleted_at TIMESTAMPTZ NULL` + 部分唯一索引 `WHERE deleted_at IS NULL`；禁止自造 `is_deleted`/`deleted` 标志。
- 默认查询（仓储层）自动过滤软删行；软删数据可见性由用例显式声明（回收站类功能），禁止隐式"全量含软删"查询。

## 5. 删除与导出（PII 相关为硬要求）

- PII 删除请求：业务表硬删 + 日志/审计侧按 security.md 脱敏原则处理；备份按保留期自然滚出。
- 数据导出（审计导出、用户数据导出）必须走脱敏管道，禁明文 PII（全局红线）。
- 导出文件视为敏感数据：交付即提醒销毁，不留存在服务目录。

## 6. 校验与大表

- 迁移 dry-run + down 验证（CI 门禁）；数据迁移行数/校验和/抽样比对 + 回滚演练。
- 大表在设计期评估分区/归档，**策略写入 Manifest**（migrations.md「大表」行），不另行走 ADR。
